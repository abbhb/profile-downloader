# 隐私与开源检查

## 权限与数据流

Manifest 仅声明 `downloads` 权限，使用 DevTools 扩展接口读取当前被检查页面的网络记录。没有站点访问授权、浏览器 Cookie API 权限、后台抓包服务、统计上报或远程扩展服务。

请求 URL、请求头、body 和响应预览可能包含敏感信息。扩展把记录保留在面板内存，最多 300 条，不写入 `chrome.storage` 或其他持久存储。清空会释放列表记录；导航默认清理，开启“保留日志”后继续保留到清空、淘汰或关闭面板。

用户点击重放后，扩展向原始目标 URL 发送一次添加 `profile` 的请求。可设置的认证头和 CSRF 头会保留，Cookie 使用浏览器当前登录状态。请求不会发送到项目维护者或第三方分析服务。原站点既有的浏览器网络行为不由本扩展控制。

Response / Preview 页按需读取原始响应，仅保留正文前 102,400 个字符作为预览；JSON 高亮与树结构使用安全 DOM，不执行响应 HTML。树节点按需展开，每组最多 100 项。

复制原始响应、格式化 JSON、Base64 文本或节点值是用户主动导出。内容会写入系统剪贴板，扩展没有新增剪贴板权限。预览截断时，为复制完整文本可再次读取 DevTools 已记录的正文，限制为 20 × 1024 × 1024 个字符；完整正文只用于本次复制，不持久缓存。不因复制向业务接口发送重放请求，剪贴板错误会明确反馈并提供已选中的文本供手动复制。

报告 HTML 通过浏览器下载保存到用户选择的位置；下载后的文件和已复制的剪贴板内容由用户管理，清空面板不会删除这些导出内容。

报告识别校验成功响应及预期 HTML / Pyinstrument renderer 结构；不能认证响应来源，也不能保证 HTML 无脚本或无敏感信息。扩展不在面板内执行报告，用户打开本地报告时仍应确认来源可信。

## 公开仓库材料

公开的是扩展源码、合成测试、文档和可审查的构建脚本。禁止提交：

- 真实 HAR、profile 报告、业务响应、浏览器导出记录或下载目录。
- 真实 Cookie、CSRF token、Authorization、API key、私钥、密码或 `.env`。
- 内部域名、私有业务地址、服务器路径、员工信息、个人邮箱或内部浏览器截图。
- 不能确认来源和授权的图片、依赖或二进制产物。

示例统一使用 `example.test`、localhost 和明显的模拟值。截图只能来自本地合成演示页；真实业务截图不能仅靠裁剪后直接开源。提交的 Git 作者邮箱应使用 GitHub 提供的 noreply 地址或获准公开的专用地址。

## 发布前检查

```sh
npm run security:check
git diff --cached --check
git diff --cached
git ls-files
```

自动检查用于发现常见秘密模式、非示例地址和不应进入包的材料；只输出位置与规则名，不回显匹配值。它不扫描 Git 历史、忽略目录或图片像素，也不能覆盖所有秘密格式。获准的文档图片路径只是文件名白名单，每次替换仍需人工复核。

人工逐项检查所有待发布文件、Git 历史、图片和附件，再检查构建 ZIP 的内容。发布包应从明确允许的扩展文件构建，不应把整个工作目录直接压缩。官方文档链接由域名白名单放行；新增来源应确认归属后更新白名单，不用全局禁用检查绕过误报。

确认不包含真实请求、业务截图、秘密、内部地址或本机路径后，才创建公开仓库、push 和 Release。发生泄露时先阻止继续传播并撤销相应凭证；删除最新文件不等于清除 Git 历史或既有 Release 附件。

# Profile Downloader v1.1.0

First public release / 首次公开发布，MIT 开源。

## What's new / 本版变化

- Compact Network-style request table with Name, Method, Status, Type, Size, Time and Waterfall; sorting, search, method/type filters, recording and preserved logs.
- Headers / Payload / Response / Timing details, with full endpoint URLs and on-demand response preview.
- Right-click a row inside Profile to select it and open profiling actions. Only clicking replay sends a request.
- Replay supported GET / POST requests with `profile=1` and download a successful Pyinstrument HTML report.
- Local synthetic tests, source and sensitive-material checks, deterministic extension ZIP and SHA-256 checksum.
- Backend compatibility, privacy and release workflow documentation.

## Install / 安装

Download the ZIP and checksum attached to this Release. Verify and extract the ZIP, then enable Developer mode at `chrome://extensions` or `edge://extensions` and choose **Load unpacked**. Select the directory containing `manifest.json`, reopen DevTools and choose **Profile**.

## Compatibility and limits / 适用范围

Chrome / Chromium-based Edge, Manifest V3. The extension uses vanilla JavaScript ES modules, HTML and CSS; Node.js 22+ is needed only for development checks and packaging.

The backend must already return Pyinstrument HTML for `profile=1`. Django's Pyinstrument middleware is an option; other applications require a compatible integration. `BKAPP_OPEN_PYINSTRUMENT` is application-specific.

The native Network request-row context menu has no public extension hook. This release provides the requested Network-style fallback in a separate Profile panel, including its own context menu.

POST runs the operation again. Only complete UTF-8 text bodies are supported; multipart, files, binary, non-UTF-8 and missing bodies are rejected. CORS, CSP, login and CSRF restrictions still apply. Cancellation does not roll back server work.

## Validation / 验证

Local Node.js v24.14.1: 29 synthetic tests passed, plus source / Manifest / version checks and the static sensitive-material preflight.

GitHub CI passed on Ubuntu / Node.js 22, Ubuntu / Node.js 24 and macOS / Node.js 22.

Browser smoke checks with mocked DevTools APIs passed for context-menu selection, GET / POST replay parameters, details, filters, numeric sorting, keyboard focus, cancellation, navigation / clear, recording, the 300-row limit, themes and narrow layouts. The fixture returns synthetic renderer HTML; this is not a real Pyinstrument backend sampling test. See [validation scope](https://github.com/abbhb/profile-downloader/blob/v1.1.0/docs/testing.md).

Real extension runtime: 10 local checks passed in isolated Chrome/133.0.6943.16 on macOS, covering real DevTools GET / POST capture, no automatic replay from the context menu, one replay per explicit click, query / mock login / CSRF / POST-body preservation and two HTML downloads through the actual extension API chain. CDP directed the downloads, so the native `saveAs` file picker was not tested. The localhost fixture returned synthetic renderer HTML; real Pyinstrument sampling and application-backend integration remain unverified.

See the repository [README](https://github.com/abbhb/profile-downloader#readme) and [documentation](https://github.com/abbhb/profile-downloader/tree/v1.1.0/docs) for usage, data handling and validation.
